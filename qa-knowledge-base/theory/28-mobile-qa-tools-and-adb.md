# 28. Инструменты мобильного QA: ADB, Инспекторы и Дебаг-утилиты

Для эффективного тестирования недостаточно просто нажимать на кнопки. Нужно уметь управлять устройством через терминал, инспектировать элементы интерфейса и использовать скрытые возможности системы.

## 1. ADB (Android Debug Bridge) — Универсальный мост
ADB — это консольная утилита, которая позволяет общаться с Android-устройством с компьютера.

### Ключевые команды, которые должен знать Junior QA:
* **Управление устройствами:**
    * `adb devices`: Список подключенных устройств (реальных и эмуляторов).
* **Работа с приложениями:**
    * `adb install path/to/app.apk`: Установка приложения.
    * `adb uninstall com.package.name`: Удаление приложения по его ID.
    * `adb shell pm clear com.package.name`: Полная очистка данных и кэша приложения (быстрее, чем через настройки).
* **Манипуляции с файлами:**
    * `adb push local_file /sdcard/`: Загрузка файла с ПК на телефон.
    * `adb pull /sdcard/remote_file`: Скачивание файла с телефона на ПК.
* **Снятие логов и медиа:**
    * `adb logcat`: Просмотр системного лога.
    * `adb shell screencap -p /sdcard/screen.png`: Снятие скриншота через терминал.
    * `adb shell screenrecord /sdcard/video.mp4`: Запись видео экрана (удобно для баг-репортов).
* **Эмуляция действий:**
    * `adb shell input tap x y`: Нажатие в определенные координаты.
    * `adb shell input text "hello"`: Быстрый ввод текста в активное поле (спасает, когда лень печатать на экранной клавиатуре).



## 2. Инспекторы интерфейса (Mobile View Inspection)
Иногда нужно узнать точный ID элемента, его размер или цвет, чтобы составить качественный баг-репорт по верстке.

* **Appium Inspector:** Самый популярный инструмент. Позволяет увидеть «дерево элементов» (как DOM в вебе), найти локаторы (ID, XPath) и даже записать шаги теста.
* **Layout Inspector (Android Studio):** Показывает 3D-модель слоев приложения. Помогает понять, какой невидимый элемент перекрывает кнопку и почему она не нажимается.
* **Accessibility Inspector (Xcode):** Инструмент для проверки доступности на iOS. Позволяет увидеть, как элементы считываются программами для слабовидящих.

## 3. Дебаг-меню и встроенные утилиты
Разработчики часто встраивают в тестовые сборки скрытые функции для QA.

* **Как найти:** Обычно вызывается долгим нажатием на логотип приложения, тройным тапом по версии сборки в настройках или «встряхиванием» (Shake) телефона.
* **Что там бывает:**
    * Переключение серверов (Prod / Stage / Dev).
    * Быстрое зачисление денег на баланс или изменение статуса заказа.
    * Локальный просмотр HTTP-запросов (аналог вкладки Network).
    * Очистка сессии без переустановки приложения.

## 4. Мониторинг производительности
Приложение может работать корректно, но «тормозить». Инструменты мониторинга показывают, почему это происходит.

* **Android Profiler / Xcode Instruments:**
    * **CPU:** Показывает нагрузку на процессор. Если график на 100% — приложение будет лагать.
    * **Memory:** Помогает найти «утечки памяти» (когда потребление RAM растет с каждым действием и никогда не падает).
    * **Network:** Визуализирует сетевую активность в реальном времени.

## 5. Дополнительные помощники
* **Scrcpy:** Утилита для отображения экрана Android-телефона на мониторе ПК. Позволяет управлять телефоном с помощью мыши и клавиатуры (очень удобно для записи багов).
* **Firebase App Distribution / TestFlight:** Инструменты для получения новых тестовых сборок. QA должен уметь проверять наличие обновлений и читать Release Notes в этих сервисах.

4. Могу ли я быстро очистить кэш через `pm clear`?
5. Получается ли найти уникальный ID кнопки через Appium Inspector?
6. Видны ли скрытые слои интерфейса в Layout Inspector?
7. Работает ли переключение стендов в дебаг-меню?
8. Корректно ли отображается сетевой трафик в Android Profiler?
9. Не превышает ли потребление памяти (Memory) критические значения при длительной работе?
10. Удалось ли снять лог падения через `adb logcat` сразу после крэша?
11. Получается ли управлять телефоном через Scrcpy (для удобства презентации бага)?
12. Работает ли эмуляция FaceID/TouchID в симуляторе Xcode?

14. Доступны ли новые сборки в TestFlight/Firebase?
15. Получается ли изменить системное время или язык через терминал для проверки кейсов?
16. Проверена ли доступность элементов (Accessibility) для экранных дикторов?
17. Нет ли лишних запросов к сети при простое приложения (мониторинг Network)?
18. Могу ли я имитировать входящий звонок через Extended Controls эмулятора?
19. Получается ли подменить GPS-координаты через инструменты IDE?
20. Совпадают ли версии сборки в приложении и в системе дистрибуции (TestFlight/Firebase)?
