# 26. Локальное хранение данных в мобильных приложениях

Мобильные приложения сохраняют часть данных непосредственно на устройстве пользователя. Это необходимо для обеспечения офлайн-работы, ускорения загрузки интерфейса и хранения пользовательских настроек. Тестировщику необходимо понимать механизмы хранения для проверки целостности данных и безопасности.

## 1. Основные типы хранилищ

### А. Настройки «ключ-значение»
Самый простой способ хранения небольших фрагментов данных (например, флаг «пройден ли онбординг» или выбранный язык).
* **Android: SharedPreferences.** XML-файлы, хранящиеся в защищенной папке приложения.
* **iOS: UserDefaults.** Аналогичный механизм для хранения простых типов данных (строки, числа, булевы значения).

### Б. Базы данных (Structured Data)
Для хранения структурированной информации (список сообщений, каталог товаров, история транзакций).
* **SQLite:** Стандартная реляционная база данных, встроенная в Android и iOS.
* **Room / Realm:** Современные надстройки над базами данных, которые упрощают работу разработчикам, но могут иметь специфические баги синхронизации.

### В. Файловая система (Internal & External Storage)
Используется для хранения тяжелого контента.
* **Кэш (Cache):** Временные файлы (миниатюры изображений, части видео). Система может удалить их автоматически при нехватке места.
* **Документы/Загрузки:** Файлы, которые должны быть доступны пользователю (например, выгруженные PDF-отчеты).



## 2. Сценарии тестирования локальных данных

### А. Миграция данных (Data Migration)
Один из самых сложных и важных тестов. Проверяется при обновлении приложения.
* **Суть:** При переходе с версии 1.0 на версию 1.1 структура базы данных может измениться. 
* **Проверка:** Необходимо установить старую версию, авторизоваться, совершить действия (добавить товары в корзину), а затем установить новую версию поверх старой. Данные не должны исчезнуть, а приложение не должно упасть при попытке прочитать «старую» базу.

### Б. Очистка данных и кэша
* **Clear Data (Android):** Полное удаление всех данных приложения (баз, настроек, файлов). Приложение должно вернуться в состояние «как после установки».
* **Clear Cache:** Удаление только временных файлов. Проверяется, не сломалась ли логика приложения при отсутствии закэшированных картинок.

### В. Работа в режиме Offline
* **Кейс:** Загрузить данные (например, ленту новостей) при наличии интернета, затем включить «Авиарежим» и перезапустить приложение.
* **Ожидаемое поведение:** Приложение должно отобразить данные из локальной базы, а не пустой экран.

## 3. Безопасность данных (Security QA)
Мобильный тестировщик должен следить за тем, чтобы чувствительные данные не хранились в открытом виде.
* **Проверка:** Пароли, токены авторизации и данные банковских карт не должны храниться в `SharedPreferences` или `UserDefaults` в виде простого текста. Для этого должны использоваться защищенные контейнеры: **Keychain** (iOS) или **EncryptedSharedPreferences / Keystore** (Android).

## 4. Как инспектировать хранилища

### Android (Android Studio):
Инструмент **App Inspection** позволяет в реальном времени просматривать содержимое SQLite таблиц и менять значения в SharedPreferences без пересборки приложения.

### iOS:
Для доступа к файлам приложения на симуляторе используются специальные пути в файловой системе Mac. Для реальных устройств используются инструменты вроде **iMazing** (на не взломанных устройствах доступ сильно ограничен из-за политики Sandbox).

## 5. Расширенный чек-лист по тестированию локальных данных

### Состояние и целостность данных
1. **Сохранение при закрытии:** Сохраняются ли данные, если принудительно закрыть приложение (Kill process) через диспетчер задач?
2. **Сохранение при разряде:** Сохраняются ли данные, если устройство выключилось из-за 0% заряда в момент записи?
3. **Дублирование:** Не создаются ли дубликаты записей в БД при многократном быстром нажатии на кнопку «Сохранить»?
4. **Валидация типов:** Как ведет себя БД, если попытаться записать строку в поле, предназначенное для чисел (актуально для миграций)?
5. **Очистка при Logout:** Удаляются ли личные данные (профиль, история) из хранилищ после выхода из аккаунта?

### Миграции и обновления
6. **Совместимость версий:** Сохраняется ли прогресс пользователя при обновлении приложения через стор (установка новой версии поверх старой)?
7. **Добавление полей:** Корректно ли работает приложение, если в новой версии в таблицу БД добавились обязательные колонки (Not Null), а в старой базе их нет?
8. **Откат версии:** (Кейс для Android) Что происходит с данными при попытке установить старую версию поверх новой (Downgrade)?

### Работа в условиях ограничений
9. **Low Storage (Мало места):** Как ведет себя приложение, если на диске осталось менее 50 МБ? Выводится ли системное предупреждение?
10. **Full Storage (Место закончилось):** Блокирует ли приложение функции записи при 0 байт свободного места, чтобы избежать повреждения файлов БД?
11. **Оффлайн-режим:** Доступны ли закэшированные данные (картинки, списки) при полном отсутствии интернета?
12. **Синхронизация:** Если данные были изменены в оффлайне, корректно ли они синхронизируются с сервером при появлении сети (кто «побеждает»: локальная версия или серверная)?

### Безопасность и приватность
13. **Открытое хранение:** Не хранятся ли пароли, CVV-коды или токены в `SharedPreferences` или `UserDefaults` в виде открытого текста?
14. **Логирование:** Не попадают ли данные из локальных БД в системный лог (Logcat), который могут прочитать другие приложения?
15. **Бекапы:** Шифруются ли локальные данные при создании резервной копии системы (Google Drive / iCloud)?
16. **Скриншоты в фоне:** (Для iOS) Скрывается ли конфиденциальная информация на скриншоте приложения в меню многозадачности?

### Управление через систему
17. **Clear Cache:** Остается ли приложение работоспособным после очистки только кэша через настройки ОС?
18. **Clear Data:** Сбрасывается ли приложение до начального состояния (экраны приветствия, выбор языка) после полной очистки данных в настройках?
19. **Внешние носители:** (Для Android) Если приложение поддерживает перенос на SD-карту, корректно ли оно работает после извлечения карты?
20. **Разрешения:** Сохраняются ли данные, если пользователь отозвал разрешение на доступ к файловой системе в настройках телефона?
21. **Многопоточность:** Не возникает ли ошибок (Database is locked), если приложение пытается одновременно записывать данные и скачивать обновление в фоне?
