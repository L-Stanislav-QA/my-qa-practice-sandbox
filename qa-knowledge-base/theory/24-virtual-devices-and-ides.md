# 24. Виртуальные устройства и среды разработки: Android Studio и Xcode

Если под рукой нет нужной модели телефона, используются виртуальные устройства. Для Android — это **Эмуляторы**, для iOS — **Симуляторы**. Разница между ними принципиальна для понимания того, что именно мы тестируем.

## 1. Различия: Эмулятор vs Симуляторы

### Эмулятор (Android Studio)
* **Принцип:** Имитирует и программное обеспечение, и аппаратную часть (железо). 
* **Точность:** Высокая. Эмулятор работает на реальном образе системы Android. Можно эмулировать специфические датчики, разряд батареи и даже входящие звонки.
* **Минусы:** Требует много ресурсов ПК (RAM и CPU).

### Симулятор (Xcode)
* **Принцип:** Имитирует только программную среду iOS поверх macOS. Он не воссоздает «железо» iPhone.
* **Точность:** Средняя. Приложение на симуляторе работает быстрее, чем на реальном устройстве, так как использует мощь процессора Mac. Многие баги производительности на симуляторе просто не видны.
* **Минусы:** Работает только на компьютерах Apple (macOS).

## 2. Работа в Android Studio для QA

Android Studio — это основная среда для разработки и тестирования под Android. Тестировщику не нужно писать здесь код, но нужно уметь управлять устройствами.

### Device Manager (AVD Manager)
Инструмент для создания виртуальных смартфонов и планшетов.
* **Настройка:** При создании устройства можно выбрать модель (например, Pixel 7), версию Android (API Level) и разрешение экрана.
* **Snapshot:** Функция «снимка» состояния. Позволяет сохранить текущее состояние системы и вернуться к нему, если тесты что-то сломали.

### Панель управления эмулятором (Extended Controls):
Вызывается нажатием на три точки `...` в меню эмулятора. Позволяет имитировать:
* **Location:** Подмена координат (GPX/KML файлы) для проверки навигации.
* **Battery:** Изменение уровня заряда и статуса (AC/Discharging), чтобы проверить поведение приложения при низком заряде.
* **Phone:** Имитация входящего звонка или SMS для проверки прерываний.
* **Display:** Проверка работы с «челками», скруглениями и разными ориентациями экрана.

## 3. Работа в Xcode для QA

Xcode — это среда для работы с iOS. Тестировщики используют её в основном для запуска симуляторов и установки сборок из исходного кода.

### Simulator App:
* **Управление:** Можно запустить сразу несколько симуляторов с разными версиями iOS.
* **Device -> Trigger Interface Orientation:** Проверка поворота экрана.
* **I/O -> Input:** Имитация сканирования FaceID или нажатия кнопки Home.
* **Debug -> Slow Animations:** Позволяет замедлить анимации, чтобы детально рассмотреть баги верстки или переходов.

### Особенности запуска сборок:
Если разработчик прислал архив с исходным кодом, QA должен уметь:
1. Выбрать целевое устройство в верхней панели Xcode.
2. Нажать кнопку **Run (Command + R)** для компиляции и запуска приложения на симуляторе.

## 4. Диагностика и подготовка окружения

### Основные задачи QA в IDE:
* **Запуск сборок:** Умение самостоятельно склонировать проект из Git и запустить его, если нет готового APK или IPA файла.
* **Управление данными:** Очистка кэша и данных приложения через настройки внутри эмулятора/симулятора.
* **Изменение настроек системы:** Включение темной темы, изменение системного шрифта, переключение языков или регионов прямо в виртуальной среде.

### Сравнение функционала для тестировщика:

| Функция | Android Эмулятор | iOS Симулятор |
| :--- | :--- | :--- |
| **Google Play Services** | Можно установить (версии с Google API) | Отсутствуют (App Store не работает) |
| **Камера** | Эмуляция (виртуальная сцена) | Не работает (или черный экран) |
| **Скорость работы** | Медленно (зависит от ПК) | Очень быстро |
| **Архитектура** | ARM или x86 | Всегда архитектура вашего Mac |

## 5. Ограничения виртуальных устройств
Важно помнить, что успешное прохождение тестов на эмуляторе не гарантирует работу на реальном девайсе. 
**Что нельзя полноценно протестировать на эмуляторах:**
1. Настоящее потребление батареи и нагрев.
2. Качество работы камеры (фокус, вспышка, QR-сканирование).
3. Работу биометрии (реальный отпечаток пальца или FaceID).
4. Специфические баги вендоров (например, баг, который проявляется только на прошивке MIUI от Xiaomi).
