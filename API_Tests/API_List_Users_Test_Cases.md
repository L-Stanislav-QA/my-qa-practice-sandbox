# Ручное тестирование API (Project: QA Sandbox)

В данном документе представлены тест-кейсы для ручного тестирования API эндпоинта `GET /api/users`.
Объект тестирования: [QA Automation Sandbox](https://github.com/manikosto/qa-automation-sandbox)

# Примечание:
Все тесты выполняются в инструменте Postman. Запросы организованы в коллекцию "QA Sandbox API".
Для всех запросов используется базовый URL: `http://localhost:8000`

# Примечание по авторизации:
Эндпоинт защищен. Перед выполнением тестов необходимо получить `access_token` через Login и подставить его в заголовок `Authorization: Bearer <token>`.

### TC-USR-LIST-01. Успешное получение списка пользователей (Happy Path)
* **Описание:** Проверка базового получения списка пользователей с параметрами по умолчанию.
* **Обоснование:** Делаем эту проверку, потому что это основной сценарий работы ручки: авторизованный пользователь должен видеть список пользователей для поиска людей, просмотра профилей и социальных взаимодействий.
* **Предусловие:**
    * Сервер и база данных запущены.
    * Пользователь `alice@buzzhive.com` авторизован.
    * Получен актуальный `access_token`.
* **Шаги:**
    1. В коллекции **QA Sandbox API** выбрать запрос **GET List Users**
    2. Проверить, что URL запроса: `http://localhost:8000/api/users`
    3. Во вкладке **Auth** выбрать тип "Bearer Token" и вставить актуальный `access_token`
    4. Query-параметры не указывать
    5. Нажать кнопку **Send**

* **Ожидаемый результат:**
    * Статус: `200 OK`
    * Ответ содержит JSON-объект с пагинацией:
    ```json
    {
        "items": [
            {
                "id": "uuid-строка",
                "username": "alice_dev",
                "display_name": "Alice Developer",
                "avatar_url": "строка или null",
                "is_verified": true
            }
        ],
        "total": 8,
        "page": 1,
        "per_page": 20,
        "pages": 1
    }
    ```
    * Поле `items` является массивом.
    * Поле `page` равно `1`.
    * Поле `per_page` равно `20`.
    * По умолчанию список отсортирован по `created_at` в порядке `desc`.

### TC-USR-LIST-02. Получение списка с пагинацией
* **Описание:** Проверка работы query-параметров `page` и `per_page`.
* **Обоснование:** Делаем эту проверку, потому что список пользователей может расти, и без корректной пагинации клиентское приложение может получать слишком много данных, медленно работать или неверно отображать страницы.
* **Предусловие:**
    * Пользователь `alice@buzzhive.com` авторизован.
    * Получен актуальный `access_token`.
    * В базе есть больше 3 пользователей.
* **Шаги:**
    1. В коллекции **QA Sandbox API** выбрать запрос **GET List Users**
    2. Проверить URL: `http://localhost:8000/api/users`
    3. Во вкладке **Auth** указать актуальный Bearer Token
    4. Во вкладке **Params** добавить:
       ```text
       page=1
       per_page=3
       ```
    5. Нажать **Send**

* **Ожидаемый результат:**
    * Статус: `200 OK`
    * В ответе `page` равен `1`.
    * В ответе `per_page` равен `3`.
    * В массиве `items` не больше 3 объектов.
    * Поле `total` содержит общее количество пользователей.
    * Поле `pages` содержит рассчитанное количество страниц.

### TC-USR-LIST-07. Запрос без токена (Unauthorized)
* **Описание:** Проверка запрета доступа к списку пользователей без авторизации.
* **Обоснование:** Делаем эту проверку, потому что эндпоинт защищен схемой `HTTPBearer`; если список пользователей доступен без токена, это может раскрыть данные пользователей анонимным клиентам.
* **Предусловие:** Нет.

    1. В коллекции **QA Sandbox API** выбрать запрос **GET List Users**
    2. Проверить URL: `http://localhost:8000/api/users`
    3. Во вкладке **Auth** выбрать "No Auth"
    4. Убедиться, что заголовок `Authorization` отсутствует
    5. Нажать **Send**

* **Ожидаемый результат:**
    * Статус: `401 Unauthorized` или `403 Forbidden`
    * Ответ содержит сообщение об ошибке авторизации:
    ```json
    {
        "detail": "Not authenticated"
    }
    ```
    * Список пользователей не возвращается.

* **Описание:** Проверка обработки строковых значений в числовых query-параметрах.
* **Обоснование:** Делаем эту проверку, потому что `page` и `per_page` должны быть integer; если сервер не валидирует типы, пагинация может работать непредсказуемо или приводить к 500 ошибкам.
* **Предусловие:**
    * Пользователь `alice@buzzhive.com` авторизован.
* **Шаги:**
    1. В коллекции **QA Sandbox API** выбрать запрос **GET List Users**
    2. Во вкладке **Auth** указать актуальный Bearer Token
    3. Во вкладке **Params** добавить:
       ```text
       page=abc
       per_page=test
       ```
    4. Нажать **Send**

* **Ожидаемый результат:**
    * Статус: `422 Unprocessable Entity`
    * Ответ содержит ошибки валидации для query-параметров `page` и `per_page`.
    * **Критично:** отсутствует ошибка `500 Internal Server Error`.
