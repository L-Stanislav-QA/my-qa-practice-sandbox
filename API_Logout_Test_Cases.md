# Ручное тестирование API (Project: QA Sandbox)

В данном документе представлены тест-кейсы для ручного тестирования API эндпоинта `/api/auth/logout`.
Объект тестирования: [QA Automation Sandbox](https://github.com/manikosto/qa-automation-sandbox)

# Примечание по авторизации:
Эндпоинт Logout защищен. Перед выполнением тестов необходимо получить `access_token` через Login и подставить его в заголовок `Authorization: Bearer <token>`.

---

## План тестирования эндпоинта POST /api/auth/logout

### 1. Блок: Happy Path (P0)
* **[LOGOUT-01] Успешный выход из системы.** Проверка деактивации текущего токена. (Ожидаемый результат: 200 OK).

### 2. Блок: Безопасность и Негативные сценарии (P1)
* **[LOGOUT-02] Выход без токена.** Проверка доступа для неавторизованных запросов.
* **[LOGOUT-03] Повторный выход с тем же токеном.** Проверка невозможности использовать токен после Logout.
* **[LOGOUT-04] Выход с некорректным/испорченным токеном.** Проверка обработки невалидных данных.
* **[LOGOUT-05] Использование просроченного токена.** Проверка реакции на истекший сеанс.

## Тест-кейсы (TC)

### TC-LOGOUT-01. Успешный выход из системы (Happy Path)
* **Обоснование:** Делаем эту проверку, чтобы подтвердить, что функция выхода работает и пользователь может корректно завершить свою сессию в приложении.
* **Шаги:**
    1. Получить актуальный `access_token` (через Login).
    2. В Postman выбрать запрос **POST Logout**.
    3. Во вкладке **Auth** выбрать тип "Bearer Token" и вставить полученный токен.
    4. Нажать **Send**.
* **Ожидаемый результат:** 
    * Статус: `200 OK`.
    * Сообщение: "Successfully logged out".

### TC-LOGOUT-02. Выход без токена (Unauthorized)
* **Обоснование:** Делаем эту проверку, потому что доступ к защищенным функциям должен быть закрыт для анонимных пользователей.
* **Шаги:**
    1. Открыть запрос **POST Logout**.
    2. Во вкладке **Auth** выбрать "No Auth" (убедиться, что заголовок Authorization пуст).
    3. Нажать **Send**.
* **Ожидаемый результат:** 
    * Статус: `401 Unauthorized`.
    * Сообщение: "Not authenticated".

### TC-LOGOUT-03. Повторный выход с тем же токеном (Blacklisting check)
* **Обоснование:** Делаем эту проверку, потому что после выхода токен должен попадать в "черный список" или удаляться. Повторное использование отработанного токена — это дыра в безопасности.
* **Шаги:**
    1. Выполнить успешный Logout (как в TC-LOGOUT-01).
    2. Сразу после этого нажать **Send** еще раз с тем же самым токеном.
* **Ожидаемый результат:** 
    * Статус: `401 Unauthorized`.
    * Сообщение: "Token has been revoked" или "Not authenticated". 
    * *Примечание: Система не должна считать нас авторизованными.*

### TC-LOGOUT-04. Выход с некорректным токеном
* **Обоснование:** Делаем эту проверку, чтобы убедиться, что сервер не принимает случайные строки вместо ключей доступа.
* **Шаги:**
    1. Во вкладке **Auth** вставить в поле токена любую случайную строку (например, `this_is_not_a_token`).
    2. Нажать **Send**.
* **Ожидаемый результат:** 
    * Статус: `401 Unauthorized` или `403 Forbidden`.
    * Сообщение: "Invalid token" или "Could not validate credentials".

### TC-LOGOUT-05. Использование просроченного токена
* **Обоснование:** Делаем эту проверку, потому что сессия имеет свой срок жизни. Использование старого токена не должно приводить к успешным действиям.
* **Шаги:**
    1. Использовать `access_token`, полученный более 30 минут назад (если время жизни по умолчанию 30 мин).
    2. Отправить запрос на Logout.
* **Ожидаемый результат:** 
    * Статус: `401 Unauthorized`.
    * Сообщение: "Token has expired".
